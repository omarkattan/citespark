WHAT IS FIXED
- Handles asynchronous PostgreSQL client and pool errors that could terminate Node.
- Aborts the GA4 import if its database lock connection is lost.
- Discards broken connections and connections whose lock release failed.
- Keeps the original error if recording failure status also fails.
- Adds a 10-second pool connection wait limit and enables TCP keepalive.
- Retains automatic imports, daily refreshes and Retry.

VALIDATION
27 targeted checks passed across connection recovery, refresh scheduling, SQL
writes, traffic totals, event context and UI states. Error events are injected
with the same message as the reported crash. SQL tests use an isolated database
and provider responses are mocked. No live Render deployment is claimed.

AFTER DEPLOYMENT
Confirm the process stays running, then open Analytics and check import status.
A job interrupted by the earlier crash can remain pending until its existing
20-minute recovery window expires. A recorded import error offers Retry.
If database connection errors continue, retain the new application logs and
check the PostgreSQL service logs for the same time. This patch handles the
connection loss but does not identify or repair its infrastructure cause.
